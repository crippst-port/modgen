=== Module Assistant (aiplacement_modgen) Upgrade Notes ===

## Upgrading to Version 0.9.0 (2026-10-30)

### Added

- Builds in Custom sections and Weekly sections courses. Each week is a section with its pre-session,
  session and post-session as core subsections. Quick Add's New Week(s) and Assessments section,
  Structure from file and Structure from prompt all work there; the course's format is never changed.
  It is off until an administrator turns on "Enable on core Moodle course formats: Weekly & Custom sections"
  (aiplacement_modgen/enable_coreformats); until then only Flexible sections courses are built in.

### Changed

- Quick Add's Assessments section has its own switch, "Enable Assessments section"
  (aiplacement_modgen/enable_assessments). It used to follow the Quick Add switch, which is now
  "Enable New Theme(s) and New Week(s)"; on upgrade it starts as that switch was.
- The settings page is reorganised: all the feature switches are under Features ("Enable AI
  generation" is now "Enable Structure from prompt"), followed by Structure from prompt, Size
  limits, CSV structure library, Help and Advice menu and Diagnostics. Names and descriptions say
  what each setting does; the setting keys are unchanged, so nothing needs reconfiguring.
- The toolbar only appears when it has an entry the user can use: one they hold the capability for,
  with its feature switched on, that the course's format can hold. Before, any Module Assistant
  capability showed it, so a teacher whose only permission was for a switched-off feature got a bar
  with nothing to press but the help links.

- format_flexsections is no longer a dependency. A Flexible sections course is still only built in
  from format_flexsections 4.1.4 on, now checked when a build starts rather than at install.
- Themes need Flexible sections, so in Custom sections and Weekly sections they are refused: New
  Theme(s) is not offered, the prompt form offers only the weekly module, and a CSV or AI structure
  with themes is refused before its preview, when approved, and if a queued job's course is switched
  to one of those formats before it runs. A week cannot go inside another section there either.
- Builds there need the Subsection activity enabled. While it is off, the toolbar says so in place
  of the Quick Add menu, and every build is refused.
- Builds there also respect the site's "Maximum number of sections", which core counts subsections
  towards, so a teacher can still add sections by hand afterwards.
- Check Structure is only offered in Flexible sections courses.
- A course in any other format is refused with a message naming the three supported formats.

### Fixed

- A build that failed part way inside one of core's own steps (adding a subsection or summary
  activity) left its database transaction open, so cron rolled it back only at the end of the task,
  taking the job's "failed" record with it, and retried even a failure that should not be retried.
  The build now rolls everything back itself, and the job records the failure.

## Upgrading to Version 0.8.3 (2026-10-30)

### Changed

- Builds never change a course's format. The plugin is only offered in Flexible sections courses,
  and every way into a build (the file and prompt page, its modal, Quick Add, and a queued job
  whose course was switched to another format) refuses any other format. This replaces 0.8.2's
  conversion of the course with update_course().
- Builds no longer add an Assessments section. Quick Add has an "Assessments section" entry
  instead, offered only at the top of the course: it adds the section straight away, under the
  build locks and the section limit, and refuses if the course already has one.
- Structure from file and Structure from prompt warn, without refusing, when the module already
  has content (an activity or resource other than Announcements, or nested sections from an
  earlier build). Empty sections and question banks do not count.
- The Quick Add and Structure from prompt forms are restyled: labels sit above their fields, each
  form opens with a line saying what it creates, the count fields have - and + buttons, the module
  format is chosen from cards, and New Theme(s) and New Week(s) show how many sections they will
  add. What the forms submit is unchanged.

## Upgrading to Version 0.8.2 (2026-10-26)

### Changed

- Each way of building a structure now needs both its own capability and its own setting:
  Structure from prompt needs aiplacement/modgen:generatewithprompt and "Enable AI"; Structure from
  file needs aiplacement/modgen:generatefromtemplate and "Enable structure from file". Before, either
  capability opened both, and building an approved structure ignored the settings.
- AI generation now also respects Site administration > AI: it is refused when no enabled provider
  offers "Generate text", or when that action is switched off for the Module Assistant placement.
- Quick Add requests are refused while Quick Add is switched off, not only hidden from the menu.
- Quick Add now changes a course's format to Flexible sections with update_course(), as building
  from a file or prompt already did, so the change is logged like one made in course settings.
- The AI policy checkbox must be ticked for the policy to be recorded as accepted.
- The Learning Activity module (mod_learningactivity) is optional. Without it, the "Add a section
  summary activity" option is not offered and builds create no summary activities. When it is
  installed, the summary activities' metadata is validated before it is stored.
- Section 0 is named and an Assessments section added only once, in a course whose section 0 has no
  name of its own yet. Builds no longer rename a section 0 the teacher has renamed, or add
  Assessments again after the teacher has renamed or deleted it.
- Builds of every kind, and the Check Structure repairs, now take the same structure locks, so they
  cannot renumber a course under each other or under a Flexible sections delete.
- Only failures that might clear on their own (a database error, a lock) are retried. Others, such
  as a capability removed after the job was queued, fail straight away instead of saying "will
  retry" until Moodle gives up.
- Building, and opening the generator, need access to the course itself (enrolment, visibility),
  not only the capability: a teacher whose enrolment is suspended can no longer build.
- Check Structure is closed while the Module Assistant is switched off, and only works on courses
  in the Flexible sections format. Clean up no longer deletes a hidden section that has a summary.

### Fixed

- Check Structure's circular reference check works on MySQL and MariaDB.
- A build whose section write fails part way now fails cleanly, instead of failing later with a
  confusing error and being retried repeatedly.
- The section limit counts what a build really creates (each week is 4 sections).
- The job status page keeps watching a job that will be retried. Jobs left waiting for a retry that
  will never run, and queued jobs whose task has gone, are now marked failed. A job that finishes
  while this check runs is no longer marked failed by mistake.
- Error messages from a build are shown as text in the generator and in course page notifications,
  not interpreted as HTML.
- The structure sent to the browser for approval no longer includes the prompt sent to the AI
  provider (which contains the site's base prompt) or the provider's raw response. This also stops
  large structures failing approval as too large.
- Regenerate on the preview goes back to the prompt form instead of leaving a spinner.
- Check Structure works when a section's stored parent is not a number, instead of failing with a
  database error.
- The preview shows titles and the prompt as written ("Q&A", not "Q&amp;A"), and the JSON download
  keeps characters such as # and %.
- When the AI answers a theme request with plain sections, their sessions, learning design metadata
  and outline are kept instead of being dropped.
- Builds respect the Flexible sections maximum section depth: a build that would nest sections too
  deeply is refused instead of creating them.
- Weekly summaries are stored as written. Filters (such as multi-language content) were being applied
  before storing, losing the other languages.
- Regenerate is only offered when generating would be allowed.
- A prompt of only spaces is refused by the server, not just the browser.
- Text that was hard-coded in English (preview, generator modal, job status) is now translatable, and
  the job page shows the course name formatted and the job state translated.
- On narrow screens the toolbar's own toggle opens it; the site menu button leaves it alone.
- Downloading a library structure outside a course needs aiplacement/modgen:managetemplates.
- A course's structure jobs are deleted with the course, and the upgrade removes jobs left behind by
  courses already deleted, so privacy requests can find every job.

### Features removed

- AI-suggested activity markers: the "View unedited suggestions" toolbar link and page, and the
  marker shown next to activities. Nothing has created markers since the activity handlers were
  removed. The upgrade drops the aiplacement_modgen_aigen table and any records left in it.

## Upgrading to Version 0.8.1 (2026-10-22)

### Fixed

- Teachers who hold only a generate capability (aiplacement/modgen:generatefromtemplate or
  :generatewithprompt) could build a structure but then hit a permissions error on the job status
  page, and never saw completion notifications. Anyone who can start a build can now follow their
  own jobs.

### Features removed

- Dates to sections (add/remove dated headings on sections), its holiday dates setting and the
  aiplacement/modgen:managedates capability. Section names that already carry a date prefix are
  left untouched and can be edited by hand.

## Upgrading to Version 0.8.0 (2026-10-21)

### Features removed

- Suggest toolbar dropdown (and the aiplacement/modgen:usesuggest capability)
- Base on existing module(s) in the generator form
- Expand on themes, Generate example content (theme introductions, suggested activities,
  session instructions)
- Hide existing sections option

Their admin settings are deleted by the upgrade. Records of previously created AI-suggested
activities are kept: unedited ones can still be reviewed from the toolbar (until 0.8.2).

## Upgrading to Version 0.2.7 (2026-01-16)

### New 'managedates' Capability

This version adds a new capability to control access to the "Dates to Sections" feature
separately from general structure management.

**New Capability:**

7. **aiplacement/modgen:managedates**
   - Apply and remove dates to course sections
   - Default: None (must be manually assigned)
   - Risk: RISK_DATALOSS
   - Context: CONTEXT_COURSE

**Action Required:**

If you previously granted users `managestructure` capability expecting them to have access
to the "Dates to Sections" feature, you must now also grant them `managedates` capability.

The `managestructure` capability now only controls access to:
- New Theme button
- New Week button

The `managedates` capability now controls access to:
- Dates to Sections button

## Upgrading to Version 0.2.6 (2026-01-14)

### New Capability System

This version introduces a granular permission system with six new capabilities replacing
the previously unused 'aiplacement/modgen:use' capability.

⚠️ **IMPORTANT: NO CAPABILITIES ARE ASSIGNED BY DEFAULT**

For security reasons, NO roles will have any Module Assistant capabilities by default.
Administrators must explicitly assign capabilities to roles after upgrading.

### New Capabilities

The following capabilities have been added:

1. **aiplacement/modgen:viewexplore**
   - View AI course insights and analytics (Explore page)
   - Default: None (must be manually assigned)
   - Risk: RISK_PERSONAL
   - Context: CONTEXT_COURSE

2. **aiplacement/modgen:managestructure**
   - Manage course structure (create themes, weeks)
   - Default: None (must be manually assigned)
   - Risk: RISK_DATALOSS
   - Context: CONTEXT_COURSE

3. **aiplacement/modgen:managedates**
   - Manage dates to sections
   - Default: None (must be manually assigned)
   - Risk: RISK_DATALOSS
   - Context: CONTEXT_COURSE

4. **aiplacement/modgen:generatewithprompt**
   - Generate content with AI prompt (Structure from prompt button)
   - Default: None (must be manually assigned)
   - Risk: RISK_DATALOSS
   - Context: CONTEXT_COURSE

4. **aiplacement/modgen:generatefromtemplate**
   - Generate content from structures (Structure from file, CSV upload)
   - Default: None (must be manually assigned)
   - Risk: RISK_DATALOSS
   - Context: CONTEXT_COURSE

6. **aiplacement/modgen:managetemplates**
   - Manage site-wide templates (admin functionality)
   - Default: None (must be manually assigned)
   - Risk: RISK_CONFIG
   - Context: CONTEXT_SYSTEM

### Action Required After Upgrade

⚠️ **MANDATORY: You MUST manually assign capabilities after upgrading.**

Without manual assignment, NO users (including administrators) will have access to
Module Assistant features.

1. **Run the upgrade:**
   ```
   php admin/cli/upgrade.php
   php admin/cli/purge_caches.php
   ```

2. **Assign capabilities to roles:**
   Navigate to: Site administration > Users > Permissions > Define roles
   
   For each role that should have access to Module Assistant features:
   - Click the role name
   - Click "Edit" button
   - Search for "modgen" in the filter box
   - Set each capability to "Allow" as appropriate
   - Click "Save changes"

3. **Recommended role assignments:**

   **For Editing Teachers:**
   - ✓ aiplacement/modgen:viewexplore
   - ✓ aiplacement/modgen:managestructure
   - ✓ aiplacement/modgen:managedates
   - ✓ aiplacement/modgen:generatewithprompt
   - ✓ aiplacement/modgen:generatefromtemplate
   - ✗ aiplacement/modgen:managetemplates (admin only)

   **For Non-Editing Teachers:**
   - ✓ aiplacement/modgen:viewexplore (analytics only)
   - ✗ All other capabilities

   **For Course Creators:**
   - Same as Editing Teachers

   **For Managers:**
   - ✓ All capabilities

### Toolbar Visibility

The Module Assistant toolbar will ONLY appear for users who have been explicitly granted
at least one modgen capability. Without any capability assignment, the toolbar will not
appear at all.

Individual buttons within the toolbar are controlled by specific capabilities:

- **New Theme / New Week:** Requires `managestructure`
- **Dates to Sections:** Requires `managedates`
- **Structure from File:** Requires `generatefromtemplate`
- **Structure from Prompt:** Requires `generatewithprompt` (also requires AI enabled in settings)

**Form Visibility:**
- **Content Placement section:** Visible to all users who can access the form

### Defense in Depth

The plugin uses a defense-in-depth security approach:

1. **Capability Check** - User must have appropriate permission
2. **Admin Setting Check** - AI features can be globally disabled
3. **Context Validation** - User must be enrolled in the course
4. **Session Key** - All write operations require valid session key

Even with capabilities assigned, AI features can still be disabled site-wide via:
Site administration > Plugins > AI Placements > Module Assistant

### Backward Compatibility

⚠️ **BREAKING CHANGE: Users who previously had access will lose it until capabilities are assigned.**

The old 'aiplacement/modgen:use' capability is no longer used. Any custom role 
assignments to this capability will have no effect and can be safely removed.

If users previously had access to Module Assistant features, they will lose access
after upgrading until you explicitly assign the new capabilities to their roles.

### Security Considerations

All modgen capabilities use appropriate risk levels:
- RISK_PERSONAL: Can view course analytics
- RISK_DATALOSS: Can create/modify course structure and content
- RISK_CONFIG: Can manage system-wide templates

Review your role assignments to ensure they align with your institution's security 
policies, particularly for capabilities with RISK_DATALOSS.

### Troubleshooting

**Problem:** Toolbar not appearing after upgrade (most common)
**Solution:** Capabilities are NOT assigned by default. You must manually assign at least
             one modgen capability to the user's role. See "Action Required" section above.

**Problem:** AI buttons (Structure from Prompt) hidden even with correct capability
**Solution:** Check Site administration > Plugins > AI Placements > Module Assistant
             Ensure "Enable AI-powered features" is checked. AI features require BOTH
             the capability AND the admin setting to be enabled.

**Problem:** "Insufficient permissions" error on specific actions
**Solution:** User needs the specific capability for that feature:
             - Structure changes: managestructure
             - Dates to sections: managedates
             - Structure from file: generatefromtemplate
             - Structure from prompt: generatewithprompt
             - Analytics: viewexplore
             - Site templates: managetemplates (CONTEXT_SYSTEM)

**Problem:** Fragment load error mentioning managestructure
**Solution:** Fragment now checks for ANY toolbar capability. User needs at least one of:
             viewexplore, managestructure, managedates, generatewithprompt, or generatefromtemplate.

For more information, see: https://github.com/your-repo/modgen/wiki/Permissions
